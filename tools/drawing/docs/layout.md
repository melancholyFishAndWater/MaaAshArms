# 版面与端口（`flow` / `cases` 的画法）

图的骨架：**横向 = 轮次（round），从左到右，不换行**——宽度不够就一直往右延伸（要换行用
`--cols-per-band N`）；**纵向 = 一轮内的执行顺序**，从上到下。

端口（连线接点）由 `--ports` 决定：

- `pos`（默认）按相邻方向定：
  - 同一列里上下相邻的节点 → **上入下出**（出口 = 上格下中，入口 = 下格上中）；
  - 跨轮左右相邻的节点 → **左入右出**（出口 = 右中，入口 = 左中，竖线走两列之间的空档）。
- `role` 是旧规则：重要节点（跨轮重复出现）左下出 / 右上进；父节点（有 `next` 的派发者）
  左下出 / 右下进。

未命中、超时、失败这类框之间留更大的间距（`--gap-error`，默认 64），不跟正常步骤挤在一起。

### 父节点分组框与角标

**父节点 = 本轮的派发者，不是配置里的层级**（图上是一个浅色分组框 + 左上角深色实心角标）：
来源是 `Node.NextList.Starting/Succeeded/Failed` 事件（`name` = 正在评估 next 表的节点、`list` =
那一刻排着的候选、`jump_back` 标出 `[JumpBack]`）。`next` 是**有序候选集**，同一节点可以被多处派发、
`[JumpBack]` 会弹回上层，所以这是**调用图不是树**；同一个父节点会在图里反复出现，别按层级读。

- **套框规则**：同一轮里**连续**由一个父节点派发的那几步套一个浅色框，框的左上角压一个深色实心角标
  （白字）写父节点名。父节点换了就另起一个框；同一个父节点跨轮重复出现就是各自独立的框
  （实测 task 200000054：4 轮里共 10 个框，`TrainingEnterOne` 一个框含 `BaseMoveUp` +
  `TrainingEnterFormation`）。
- **配色**：同名父节点永远同一套颜色（一眼看出"又是它派发的"），不同父节点按**首次出现顺序**轮换
  `PARENT_COLORS` 里的 6 套（蓝 / 青绿 / 琥珀 / 紫 / 绿 / 玫红，都是浅底 + 同色系边框 + 深色角标）。
  超过 6 个父节点就循环取色，此时靠角标文字区分。
- **不入框的三种**：任务起止框（`kind == "task"`）、`父 未记录`（没归上派发者）、**自派发/自循环**
  （父节点就是自己）——第三种在图上是那个"循环节拍"节点自己：它派发别人（它开头标着角标的框），
  别人弹回它，所以它夹在框之间。
- 框里那一行 `候选：…`：带 `√` 的是**本次真跑的那个**（按候选表里的位置认，重名时只标第一个），
  带 `弹回` 的是 `[JumpBack]` 候选，`另 N 项` 表示还有几个候选没列出来（框里只列
  `PARENT_CHOICE_LIMIT` 个，`--list` 给全）。派发者名字已经在角标里，所以这一行不再重复写它。
- `父 X（自派发/自循环）`：`list` 里含自己。**入口那一轮是框架合成的自派发**
  （`TaskTraining -> [TaskTraining]`），与"配置里写的自循环"（`BattleWin -> […, BattleWin, …]`）
  在日志里长得一样，工具不猜是哪种。
- 三种退回依次是 `Node.NextList` → `[cur_node_=X]`（只知道派发者、不知道候选表）→ 该 task 的入口名，
  都不成立才是 `父 未记录`；超时/`node not completed` 这类失败事件按**它自己报的节点名**去查表
  （没有被选中进候选表的 `Task timeout` pretask 查不到，属正常）。
- **整张图一条候选都没有时**（日志里没有 `Node.NextList`，例如只导出到某一段）：不逐个框写"父 未记录"，
  只在图上第二行注记一次；`--no-parents` 关掉分组框与那一行（图会矮一截）。`--list` 始终打印候选，不折叠。

### 重复轮次合并成一列（`--no-overlay` 关闭，`--overlay-min` 调阈值，默认连续 2 轮）

日志里"同一个循环跑几十遍"很常见（实测一份 40 轮的日志里 34 轮是同形的两步：
`ReturnBattleMainPage → BattleInHome`，每轮都没截图），逐轮各占一列会让图宽到没法读。
合并条件四条**同时**成立，任一条不满足就在那里断开（不是整段作废）：

1. **签名相同**：`(节点名, 种类, 折叠次数, 是否完成)` 逐项从**列首**对齐。种类含 `未命中（聚合）`，
   所以「`B,C,D,E`」与「`B,C,D,E` + `未命中 ×5`」是两种形状；`×3` 的一格也不等于逐次三格。
2. **连续**：中间夹一轮别的形状就断成两段。
3. **整轮无贴图**：`--vision` / `--on-error` 一条都没贴上才算（有图本身就是信息）。
4. **整轮无失败框**：`node not completed` / `Task timeout` / `invalid node id` 一律不折——
   折进 `×N` 等于把"这次崩了"藏起来。

- 合并列画**首轮**的步骤（时间戳是真实的，不复制、不改 `Step`），列头写
  「第 a–b 轮 · ×N 重复 · 首轮起–末轮止」，底色转琥珀、右侧一根橙竖条；末端那列若也有失败框，
  会各自独立成一列。
- 图上第二行写「N 段重复已合并 → M 列」，图例末尾多一项「合并列」。
- **判定发生在贴图解析之后**，所以 `--no-thumbs` 时所有轮都算"无图"（这个开关本来就不看贴图），
  与"证据包里没有图片"是同一个结果。
- `--no-overlay` 的产物与加这个功能之前**逐字节相同**（实测 sha256 一致），要逐轮时间就关掉它。
- 前缀差一步的两轮**不合并**（`A,B,C,D,E` 与 `B,C,D,E`）：短的那轮是从中间开始的，硬折会让列头
  写的轮号区间与实际首尾不符；只从列首逐项比（见 `AGENTS.md` 的功能取舍）。

### 视觉尺寸开关

| 开关 | 默认 | 作用 |
| --- | --- | --- |
| `--thumb-height` | 132 | 缩略图高度 px |
| `--box-width` / `--box-height` / `--font-size` / `--scale` / `--title` | 各有默认 | 框宽高、字号、整体缩放、标题 |
| `--gap-y` / `--gap-x` | 36 / 120 | 同一列内的间距 / 列间距 |
| `--gap-error` | 64 | 未命中、超时、失败框的额外间距 |
| `--collapse` | 3 | 连续同节点折叠为 `未命中 ×N`；`1` = 逐次各占一列 |
